# IRIS Experience Standard

## Purpose

This document is the product-quality contract for the IRIS face. It applies to every consumer-facing surface, not only the home screen.

IRIS competes with the best consumer experiences across financial technology, AI, search, productivity, education, decision support, and premium software. The objective is not visual imitation. The objective is a more coherent intelligence experience.

## Non-negotiable product principles

1. **Intelligence leads.** The interface exposes what the governed intelligence runtime can establish; screens never become the source of truth.
2. **Evidence is visible.** Every material conclusion has an epistemic state and, where available, a path to its supporting evidence and lineage.
3. **Unknown is designed.** Missing, insufficient, limited, unresolved, and not-applicable states are first-class experiences. They are never silently converted to zero or a reassuring conclusion.
4. **No dead-end intelligence.** A meaningful result should provide a natural next exploration: understand, inspect evidence, compare change, investigate a relationship, explore a scenario, or review a decision.
5. **Progressive disclosure.** The first layer is simple and human. Deeper layers expose reasoning, evidence, lineage, assumptions, uncertainty, and technical provenance without overwhelming the user.
6. **One connected financial life.** Accounts, transactions, balances, identity, assets, liabilities, investments, statements, derived intelligence, reports, decisions, and outcomes are experienced as one connected system rather than disconnected widgets.
7. **Recursive by design.** The face must accommodate intelligence that emerges from arbitrary graph depth. The UI cannot depend on a fixed number of intelligence categories or widgets.
8. **User agency.** The user controls report activation, attention, exploration, questions, and product preferences. User controls never bypass evidence or certification boundaries.
9. **Truth over completion.** A beautiful empty state is better than a fabricated answer. A constrained answer is better than false certainty.
10. **Calm sophistication.** Visual hierarchy, motion, typography, spacing, and interaction should communicate confidence without theatrical claims about certainty.
11. **Accessible everywhere.** Keyboard navigation, focus states, reduced motion, readable contrast, touch targets, responsive layouts, and screen-reader semantics are product requirements.
12. **Performance is part of trust.** Loading states explain what IRIS is doing without implying that unavailable results already exist. Stale data must be distinguishable from current data.

## Face architecture

The consumer experience should progressively move through:

`IRIS → What matters → Why it matters → What changed → How Iris knows → What could happen → What can be decided → What happened → What Iris learned`

These are experience modes, not fixed intelligence levels. A new intelligence composition can enter the same surfaces without requiring a new hierarchy level.

## Core surfaces

- **IRIS:** the user's primary intelligence entry point.
- **My Financial Life:** connected state and relationships across evidence domains.
- **What Matters:** prioritized supported intelligence, ranked by materiality and usefulness.
- **What Changed:** temporal intelligence and meaningful change since a supported comparison point.
- **Ask IRIS:** natural-language entry into governed question-specific intelligence.
- **Understand:** progressive explanation from conclusion to reasoning to evidence.
- **Intelligence:** exploration of the recursive graph and higher-order intelligence where publication permits it.
- **Reports & Analytics:** user-controlled products generated from governed intelligence.
- **Decisions:** evidence-linked choices, consequences, scenarios, and recommendations.
- **Outcomes & Learning:** observed results and learning only when real outcome evidence exists.
- **Evidence:** provenance, freshness, limitations, and reverse traversal.

## Interaction standard

Every important intelligence object should support, when applicable:

`See → Understand → Verify → Explore → Compare → Ask → Decide`

The UI must never expose an action whose backend contract does not actually exist. Navigation to an unavailable capability must not masquerade as completed functionality.

## Publication standard

The face may display a user-specific financial conclusion only when the backend publication boundary permits it. UI state, catalog metadata, capability existence, provider availability, consent, and activation are not financial observations.

## Visual standard

IRIS should feel premium, quiet, dimensional, and intelligent rather than like a conventional banking dashboard. Large moments should communicate meaning. Dense evidence views should become precise and inspectable. Motion should explain state changes, not decorate uncertainty.

The visual system must remain coherent across mobile and desktop and must not depend on a single viewport size.

## Anti-fabrication UX contract

The frontend must never invent:

- financial values;
- transactions;
- institutions or accounts;
- dates or periods;
- probabilities or confidence values;
- intelligence results;
- evidence records;
- outcomes;
- provider observations.

When a value is unavailable, the interface must preserve the backend state and explain the limitation where useful.

## Certification boundary

This standard does not certify any current UI or runtime. A surface becomes certified only after its actual frontend/backend contract, live evidence behavior, interaction behavior, deployment, and end-to-end journey are independently verified.
